## 功能概述

### 🎯 什么是AI协议生成？

AI协议生成功能允许您通过提供**原始16进制数据样本**和**解析规则描述**，让Claude AI自动分析并生成完整的协议配置，无需手动逐个配置字段。

### ✨ 核心优势

- **节省时间**：几分钟完成原本需要几小时的配置工作
- **准确性高**：AI自动推断数据类型、缩放因子、字节序
- **灵活通用**：支持任意格式的协议描述
- **即时验证**：生成后可立即测试和调整

### 🔧 AI能够自动分析

| 分析项 | 说明 |
|--------|------|
| **帧结构** | 帧头、帧尾、长度字段位置 |
| **校验方式** | Sum/XOR/CRC8/CRC16/CRC32 |
| **数据字段** | 字段名称、类型、位置、长度 |
| **缩放因子** | 根据转换公式计算scale/offset |
| **字节序** | 大端序/小端序自动识别 |
| **单位范围** | 合理的单位和最大/最小值 |

## 前置准备

### 1️⃣ 获取Claude API密钥

访问 [Anthropic Console](https://console.anthropic.com/) 获取API密钥：

1. 注册/登录Anthropic账号
2. 进入 **API Keys** 页面
3. 点击 **Create Key** 创建新密钥
4. 复制密钥（格式：`sk-ant-api03-...`）

> ⚠️ **重要**：API密钥是私密信息，请妥善保管，不要提交到代码仓库！

### 2️⃣ 配置API密钥

有两种配置方式：

#### 方式A：环境变量（推荐）

**Windows:**
```bash
# 临时设置（当前会话）
set ANTHROPIC_API_KEY=sk-ant-api03-your-key-here

# 永久设置（系统环境变量）
1. 右键"此电脑" → 属性 → 高级系统设置
2. 环境变量 → 新建
3. 变量名: ANTHROPIC_API_KEY
4. 变量值: sk-ant-api03-your-key-here
```

**Linux/macOS:**
```bash
# 临时设置
export ANTHROPIC_API_KEY=sk-ant-api03-your-key-here

# 永久设置（添加到 ~/.bashrc 或 ~/.zshrc）
echo 'export ANTHROPIC_API_KEY=sk-ant-api03-your-key-here' >> ~/.bashrc
source ~/.bashrc
```

#### 方式B：配置文件

编辑 `Settings.ini`（GenericScope程序根目录）：

```ini
[AI]
ApiKey=sk-ant-api03-your-key-here
```

### 3️⃣ 网络连接

确保计算机能够访问 `https://api.anthropic.com`

## 快速开始

### 5分钟上手示例

1. **启动GenericScope** → 点击右上角 **设置⚙️** → **协议配置**

2. **新建协议** → 点击 **新建** 按钮

3. **选择模板** → 在下拉框中选择 **"🤖 AI智能生成"**

4. **输入协议名称**：`IMU_Protocol_AI`

5. **点击"创建"** → 进入AI输入对话框

6. **粘贴示例** → 点击 **粘贴示例** 按钮（自动填充演示数据）

7. **生成协议** → 点击 **生成协议** 按钮

8. **等待生成** → AI分析中（约10-30秒）

9. **完成！** → 协议配置自动生成并填充到配置界面

## 详细使用步骤

### 步骤1：打开AI生成对话框

```
主界面 → 设置⚙️ → 协议配置 → 新建 → 选择"🤖 AI智能生成" → 创建
```

### 步骤2：填写原始数据样本

在 **"原始16进制数据样本"** 文本框中输入完整的数据包：

**格式要求：**
- 16进制字符（0-9, A-F）
- 可以用空格分隔，便于阅读
- 至少一条完整的数据帧

**示例：**
```
AA55 0101 2E00 C7F6 2901 601C 0000 0266 F7FF 38DA FFFF 959B 0100 C9C9 0E00 6104 EDFF BF46 1810 D4FF 0000 E1FF 0000 40FF 0000 0000 DC7E
```

### 步骤3：描述解析规则

在 **"解析规则描述"** 文本框中详细描述协议解析方式：

**应包含的信息：**
- 数据起始位置和长度
- 数据类型（int8/16/32, float, double等）
- 字段排列顺序
- 转换公式/缩放因子
- 字节序说明（可选）
- 帧头、帧尾、校验信息（如有）

**示例：**
```
原始数据从第7字节开始，取44字节，按照小端int32模式解析为11个数据
数据排列顺序：时间戳、温度、角速度(3个)、加速度(3个)、欧拉角(3个)

转换公式：
- 温度/256 = 实际温度
- 角速度/65536/1000000*量程 = 实际角速度
- 加速度/65536/32768*量程 = 实际加速度
- 欧拉角转成I16后*180/32768 = 实际欧拉角

帧头：AA55
帧尾：DC7E
```

### 步骤4：生成协议

1. **检查输入** → 确认数据和规则描述完整
2. **点击"生成协议"** → AI开始分析
3. **查看进度** → 进度条显示生成状态
4. **等待完成** → 通常需要10-30秒

### 步骤5：验证和调整

生成完成后：

1. **查看字段列表** → 检查AI生成的所有字段
2. **验证缩放因子** → 重点检查scale值是否正确
3. **调整细节** → 可手动修改字段名称、单位、范围等
4. **保存协议** → 点击 **生成协议** 保存到ProtocolManager

### 示例2：串口温度传感器协议

#### 输入数据：
```
FF AA 01 05 00 1A 0C 5F 02 0D 0A
```

#### 解析规则：
```
帧头：FF AA
功能码：01
数据长度：1字节（第4字节）
数据域：温度值（2字节，大端序int16）
校验：CRC16-MODBUS（2字节）
帧尾：0D 0A

温度转换：原始值/10.0 = 实际温度（°C）
```

#### AI生成结果：

AI会自动识别：
- 帧头：`FF AA`
- 帧尾：`0D 0A`
- 长度字段位置：3
- 校验类型：CRC16_MODBUS
- 温度字段：`elementHead=5, type=Int16, scale=0.1, unit=°C`

## 技术原理

### 系统架构

```
┌─────────────────────┐
│ AIProtocolInputDialog│  用户输入界面
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│ ProtocolAIGenerator │  AI生成引擎
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│  Claude API         │  远程AI服务
│  (Anthropic)        │
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│  ProtocolConfig     │  生成的协议配置
└─────────────────────┘
```

### AI提示词设计

系统使用精心设计的提示词引导Claude AI：

1. **角色定位**：将AI定位为"协议解析专家"
2. **任务分解**：
   - 分析帧结构
   - 推断校验方式
   - 解析数据字段
   - 判断字节序
3. **输出规范**：要求严格的JSON格式输出
4. **示例引导**：提供完整的配置结构示例

### 数据流程

```
1. 用户输入
   ├─ 原始16进制数据
   └─ 解析规则描述
          ↓
2. 构建提示词
   └─ 包含任务要求和输出格式
          ↓
3. 调用Claude API
   ├─ Model: claude-3-5-sonnet-20241022
   ├─ Max Tokens: 4096
   └─ Temperature: 0.3 (更确定的输出)
          ↓
4. 解析AI响应
   ├─ 提取JSON
   ├─ 验证格式
   └─ 转换类型
          ↓
5. 生成ProtocolConfig
   └─ 填充到配置界面
```

### 类型转换

AI返回的字符串类型需要转换为GenericScope内部枚举：

```cpp
// 数据类型转换
"Int32" → CommandSettingsDialog::DataType::Int32
"Float" → CommandSettingsDialog::DataType::Float

// 校验类型转换
"CRC16_MODBUS" → CommandSettingsDialog::ChecksumType::CRC16_MODBUS

// 字节序转换
"LittleEndian" → CommandSettingsDialog::ByteOrder::LittleEndian
```

## 常见问题

### ❓ API密钥相关

**Q1：如何获取API密钥？**

A：访问 https://console.anthropic.com/ 注册账号并创建API密钥。

**Q2：API密钥收费吗？**

A：是的，Claude API按使用量计费。每次生成协议约消耗 $0.005-0.01（约0.03-0.07元人民币）。新用户通常有$5免费额度。

**Q3：配置的API密钥在哪里存储？**

A：
- 环境变量：系统级，其他程序不可见
- Settings.ini：应用级，明文存储（建议仅用于测试）

**Q4：能否使用其他AI服务？**

A：当前版本仅支持Claude API。未来可能支持其他兼容的AI服务。

---

### ❓ 使用过程问题

**Q5：生成失败，提示网络错误？**

A：可能的原因：
1. API密钥未配置或错误
2. 网络无法访问 api.anthropic.com
3. 防火墙拦截HTTPS请求

**解决方案**：
- 检查API密钥是否正确
- 使用代理或VPN
- 关闭防火墙/杀毒软件临时测试

**Q6：AI生成的缩放因子不准确？**

A：AI基于描述推断，可能存在误差。**建议**：
1. 在解析规则中明确写出计算公式
2. 生成后手动验证关键字段的scale值
3. 使用测试数据验证解析结果

**Q7：生成速度慢？**

A：正常情况下需要10-30秒。影响因素：
- 网络延迟
- API服务器负载
- 数据复杂度

**Q8：能否批量生成多个协议？**

A：当前版本仅支持单个协议生成。批量生成功能在开发计划中。

---

### ❓ 协议配置问题

**Q9：AI能识别哪些校验方式？**

A：支持识别：
- None（无校验）
- Sum（累加和）
- XOR（异或）
- CRC8
- CRC16-MODBUS
- CRC16-CCITT
- CRC32

**Q10：如何处理混合字节序？**

A：在解析规则中明确说明：
```
数据字段：小端序
校验码：大端序
```

AI会自动设置 `byteOrder` 和 `checksumByteOrder`。

**Q11：生成的协议配置能否修改？**

A：可以！生成后可在协议配置界面手动调整任何参数。

**Q12：能否保存AI生成的协议模板？**

A：可以通过"导出协议"功能导出为JSON，下次直接导入即可。

## 最佳实践

### ✅ 编写高质量的解析规则

**好的示例：**
```
协议名称：温湿度传感器协议V2

帧结构：
- 帧头：0xFF 0xAA（固定）
- 数据长度：1字节（第3字节，表示后续数据字节数）
- 数据域：
  * 设备ID（1字节，uint8）
  * 温度（2字节，int16，小端序）
  * 湿度（2字节，uint16，小端序）
  * 时间戳（4字节，uint32，小端序，单位ms）
- 校验：CRC16-MODBUS（2字节，小端序，校验整个帧）
- 帧尾：0x0D 0x0A

数据转换：
- 温度：原始值 / 10.0 = 实际温度（°C），范围 -40 ~ 80
- 湿度：原始值 / 10.0 = 实际湿度（%RH），范围 0 ~ 100
- 时间戳：无需转换，单位ms

示例数据：
FF AA 09 01 01 2C 02 BC 00 00 10 00 00 A3 B2 0D 0A
```

**差的示例：**
```
数据是从第几个字节开始的，有温度湿度
```

### ✅ 提供完整的示例数据

- 至少提供一条完整的数据帧
- 最好提供2-3条不同的数据样本
- 确保数据包含所有字段

### ✅ 明确说明特殊处理

如果有特殊的数据处理逻辑，务必说明：

```
注意：
1. 角速度字段虽然是int32，但需要先转换为int16再计算
2. 欧拉角有符号扩展需求
3. 量程参数可配置（默认为1）
```

### ✅ 验证生成结果

生成后必须验证：

1. **字段数量**：是否与预期一致
2. **数据类型**：是否正确识别
3. **缩放因子**：**重点检查**，使用测试数据验证
4. **字节偏移**：是否符合协议规范
5. **校验方式**：是否正确

### ✅ 保存和复用

对于常用协议：

1. 生成后导出为JSON模板
2. 保存到 `protocols/` 目录
3. 下次直接导入，无需重新生成

## 附录

### A. 支持的数据类型

| 类型 | 说明 | 字节长度 |
|------|------|----------|
| Int8 | 有符号8位整数 | 1 |
| UInt8 | 无符号8位整数 | 1 |
| Int16 | 有符号16位整数 | 2 |
| UInt16 | 无符号16位整数 | 2 |
| Int32 | 有符号32位整数 | 4 |
| UInt32 | 无符号32位整数 | 4 |
| Float | 32位浮点数 | 4 |
| Double | 64位浮点数 | 8 |
| MByte | 多字节整数（可变长度） | 1-8 |
| String | 字符串 | 可变 |

### B. 支持的校验算法

| 算法 | 多项式/方法 | 适用场景 |
|------|------------|----------|
| None | - | 无校验 |
| Sum | 累加和 | 简单校验 |
| XOR | 异或 | 简单校验 |
| CRC8 | 0x07 | 短数据包 |
| CRC16-MODBUS | 0xA001, 初值0xFFFF | MODBUS协议 |
| CRC16-CCITT | 0x1021, 初值0xFFFF | 蓝牙/Zigbee |
| CRC32 | IEEE 802.3 | 高强度校验 |

### C. 字节序说明

**小端序（LittleEndian）**：
- 低字节在前，高字节在后
- 示例：0x1234 存储为 `34 12`
- 常用于：x86/x64架构、大多数嵌入式系统

**大端序（BigEndian）**：
- 高字节在前，低字节在后
- 示例：0x1234 存储为 `12 34`
- 常用于：网络协议、MODBUS
